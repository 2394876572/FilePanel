## 0. 一句话目标

把一个自包含的绿色软件丢进任意文件夹，双击后在 1~3 秒内展示该文件夹（含全部子文件夹）所有文件的
**文件名 / 类型 / 所在位置 / 创建时间 / 修改时间 / 大小**，支持**搜索、打开、改名、删除、批量改名、
收藏打标签、最近使用置顶**，并在离线、免装 Java 的 Windows 上直接运行。

## 1. 环境实测结论（方案的事实基础）

本节全部为本机实测结果，是后续技术选型的依据。

| 检测项 | 实测结果 | 结论 |
|---|---|---|
| 操作系统 | Windows 10 (10.0.19045) x64 | 只面向 Windows，不跨平台 |
| JDK 17 | `C:\jdk17` = Oracle JDK **17.0.19+9-LTS**，含 `jpackage` / `jlink` / `jmods` | ✅ 可产出**免装 Java 的自包含 exe** |
| JDK 8 | `C:\jdk-1.8` = Oracle JDK **1.8.0_441**，`jre\lib\ext\jfxrt.jar` **存在** | JavaFX 8 已内置，可作为零下载兜底方案；但无 jpackage |
| 当前 `JAVA_HOME` | `C:\jdk-1.8` ⚠️ | **最大隐患**：构建脚本必须显式覆盖为 `C:\jdk17` |
| Maven | PATH 无；IntelliJ 内置于 `…\IntelliJ IDEA\plugins\maven-plugin\lib\maven3` | 需在 M0 落地 Maven（下载独立版，IDEA 版作回退） |
| 网络 | Node / JVM 实测可达 Maven Central（HTTP 200） | 依赖可正常下载；`curl`/`Invoke-WebRequest` 的 TLS 报错是沙箱限制，不影响构建 |
| Node | v24.19.0 | 仅作备选路线，不使用 |
| Python / .NET / Rust | 均无（`python` 仅为商店占位符） | 排除 PySide / WPF / Tauri |
| 本地仓库 | `~\.m2\repository` 已有大量缓存，**含 JNA 5.7.0 / 5.13.0 / 5.18.1** | 回收站、系统图标所需 JNA 可离线获取 |
| 磁盘 | C 盘可用空间需在 M0 复核（`--type app-image` 约需 300MB 余量） | M0 检查项 |

### 1.1 目标文件夹规模实测

| 指标 | 数值 |
|---|---|
| 文件总数 | **1245** |
| 目录总数 | 194 |
| 总占用 | 268.6 MB |
| 最大目录深度 | 12 层 |
| **噪声占比** | `某项目\collector\.venv` 一个目录含 **1149 个文件**（其中 497 个 `.pyc`） |
| 排除噪声后的有效文件 | **约 170 个** |

**这条数据直接决定了产品的核心设计**：不做默认排除，界面会被 1100 个 `pip` 源码文件淹没。
因此"排除规则"不是可选项，而是**第一优先级功能**（详见 §5.2）。

## 2. 可行性结论

### 2.1 结论：可行，且性能不是瓶颈

- **扫描性能**：1245 个文件读全属性在百毫秒级；即使 10 万文件也就 1~3 秒。放后台线程 + 真实进度回推即可，
  用户要的"正在读取当前文件夹及子文件夹的文件信息"可以做成**带计数和当前路径的真进度**，而不是假动画。
- **搜索性能**：全部元数据在内存，`FilteredList` 过滤 1 万行是毫秒级，输入即响应。
- **渲染性能**：JavaFX `TableView` 原生虚拟化，10 万行不卡；只要不一次性 new 大量 Node。

### 2.2 真正的技术难点（已识别，均有对策）

| 难点 | 风险 | 对策 |
|---|---|---|
| `.venv` / `node_modules` 等噪声目录 | 中 | 目录级剪枝（`preVisitDirectory` 返回 `SKIP_SUBTREE`），并在界面显式提示"已隐藏 N 项" |
| Windows 真实系统图标（HICON → JavaFX Image） | **高** | 排在 M8，先 PoC；失败则降级为内置矢量图标（视觉反而更统一） |
| Office 文档内容搜索 | 中 | `.docx/.xlsx/.pptx` 本质是 ZIP+XML，用 JDK 内置 `java.util.zip` 直接解析，**零依赖可实现** |
| `JAVA_HOME` 指向 JDK 8 | **高** | 所有构建脚本顶部硬编码 `set JAVA_HOME=C:\jdk17` |
| jpackage 中文应用名/路径 | 低 | app-image 名用 ASCII `FilePanel`，界面显示名用中文"文件面板" |
| 权限不足目录（`某项目`、系统目录） | 中 | 捕获 `AccessDeniedException` 跳过并计数，界面汇总提示"跳过 N 个无权限目录" |
| 超长路径 / 符号链接 / junction | 低 | 不跟随符号链接；超长路径用 `\\?\` 前缀；M0 专项测试 |
| 杀毒/EDR 对自制 exe 的拦截 | 中 | 打包产物需加白名单；在《使用说明》中说明 |

### 2.3 明确非目标（v1 不做）

不做文件同步/云盘/FTP；不做文件内容编辑；不做多窗口多标签页；不做权限与用户管理；
不做非 Windows 平台；不做安装包（`--type msi/exe` 需要 WiX，只出 `app-image` 绿色目录）。

## 3. 技术选型（已确认）

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | **Java 17** | 复用你 5-6 年 Java 经验，长期可自行维护 |
| UI | **JavaFX 17.x（LTS，`javafx-controls` + `javafx-fxml`）** | 原生桌面窗口；TableView 自带虚拟化/排序/列宽/自定义单元格；CSS 可深度美化 |
| 构建 | **Maven 3.9.x** + `javafx-maven-plugin` | IDEA 友好；`mvn javafx:run` 一键调试 |
| 打包 | **`jpackage --type app-image` + `jlink` 裁剪运行时** | 免装 Java、绿色目录、拷走即用；无需 WiX |
| 本机互操作 | **JNA 5.18.x**（回收站、可选系统图标） | 本机 `.m2` 已有，可离线获取 |
| 序列化 | **Jackson databind**（配置/最近/标签/索引缓存） | 业界标准、你熟悉；若想零依赖可换 Gson 或手写 |
| 测试 | **JUnit 5** + 测试样本目录生成器 | 扫描/命名冲突/批量改名算法必须有自动化测试 |

**为什么不选其他路线（备查）**：
- **Java 8 + JavaFX 8**：零下载，但 JavaFX 8 已 EOL，无 `jpackage`（免装 Java 打包要额外装 Inno Setup），
  且没有 `var`/`record`/`switch` 表达式，代码更啰嗦。仅作下载依赖失败时的兜底。
- **Node + 浏览器面板**：UI 开发最快最漂亮，但启动后是"浏览器标签页"而非独立面板，且需常驻 node 进程。
- **Electron**：体积 250MB+，与你的技术栈不匹配。

## 4. 系统架构

### 4.1 目录与部署形态（核心设计）

> **⚠️ 形态已变更（v1.2，2026-09-20）**：下面是初版设计（`FilePanel\` 子目录 + `.bat` 入口）。
> **实际交付改为"平铺部署"**：不再有 `.bat`，`FilePanel.exe` 直接放在被管理文件夹的顶层。
> 本节保留初版设计是为了说明这次演进的原因。

**初版设计（已废弃）**：

```
项目文件夹\                            ← 【扫描根目录】= 你把启动器丢进来的目录
├─ 启动文件面板.bat                   ← 双击入口（传入 --root "%~dp0"）
├─ FilePanel\                        ← 自包含程序目录（jpackage app-image 产物）
│  ├─ FilePanel.exe                  ← 本体（ASCII 名，规避编码坑）
│  ├─ app\                           ← 应用 jar + 依赖 jar
│  └─ runtime\                       ← jlink 裁剪后的 JRE（用户无需装 Java）
├─ .filepanel\                       ← 【便携数据目录】配置/最近/收藏/标签/索引缓存
│                                      默认自动排除，不出现在列表里
└─ …你原有的文件与文件夹
```

**废弃原因**：用户明确要求"做成用户属性的 exe 启动，不要 `.bat`"——
`.bat` 会闪一个控制台窗口、没有图标，右键属性里也不是一个正常的程序。

**实际形态（平铺部署）**：

```
<被管理的文件夹>\                    ← 扫描根目录 = 程序自己所在的位置
├─ FilePanel.exe                     ← 真正的 exe 入口（无控制台、带图标、有版本属性）
├─ FilePanel.ico
├─ app\                              ← 程序自身（jar + FilePanel.cfg）  ← 自动隐藏
├─ runtime\                          ← 自带 JRE（含 JavaFX）           ← 自动隐藏
├─ .filepanel\                       ← 数据目录（隐藏，运行时生成）      ← 自动隐藏
└─ …你原有的文件与文件夹
```

程序自己的 `app\`、`runtime\`、`FilePanel.ico` 按**精确路径**自动隐藏——不按名字，
否则用户自己在别处建的 `app` 目录也会被无端藏起来。`FilePanel.exe` **保留可见**，
那是用户要双击的入口。

工程源码目录：

```
FilePanel\                       ← 默认自动排除，不污染视图
├─ pom.xml
├─ tools\apache-maven-3.9.9\         ← 项目内 Maven（不进版本库）
├─ tools\m2repo\                     ← 项目内依赖仓库（全局 ~\.m2 不可写）
├─ scratch\                          ← 一次性工具与验证输出（已 gitignore）
├─ docs\                             ← 实施笔记、三份说明文档、截图
├─ scripts\                          ← mvn / build / run / scan / selftest / uiselftest /
│                                      screenshot / package / _java / fetch-maven.mjs
└─ src\main\java\com\zean\filepanel\ ← core / ops / store / ui / ui\dialog / win
```

### 4.2 根目录解析规则（用户已确认：放进哪个文件夹就管哪个）

优先级从高到低：

1. 命令行参数 `--root "路径"`（顶层 `启动文件面板.bat` 传入自身所在目录）
2. 上次使用的根目录（`config.json` 记忆）
3. **exe 所在目录的父目录**（因为 exe 规范位置是 `<根>\FilePanel\FilePanel.exe`，父目录即根）
4. exe 所在目录
5. 用户主目录，并弹出文件夹选择框

补充交互：
- 支持把文件夹**拖到 exe / bat 上**直接切换根目录
- 界面顶部始终显著显示当前根目录，并提供"切换文件夹"按钮
- 首次启动若判定结果存疑，弹一次确认框

```

                       │

                       │

                       │
服务层  OpenService / RenameService / BatchRenameService / DeleteService / ContentIndexer
                       │
状态层  RecentStore / FavoriteStore / TagStore / ConfigStore（JSON 持久化）
                       │

                       │
系统层  win\Shell32（JNA：回收站、可选系统图标）
```

### 5.2 排除规则（最高优先级功能）

**默认排除目录名（匹配即整棵子树剪枝）**：
```
.venv  venv  env  __pycache__  node_modules  .git  .svn  .hg
.idea  .vscode  target  build  dist  out  obj  bin
.gradle  .m2  .cache  .filepanel  FilePanel  FilePanel
$RECYCLE.BIN  System Volume Information
```
**默认排除文件名**：
```
~$*（Office 临时文件）  *.tmp  *.pyc  *.pyo  *.class  Thumbs.db  desktop.ini  .DS_Store
```
**界面要求**：
- 底部状态栏始终显示"已隐藏 N 项（含占用 X MB）"，点击可展开查看被隐藏的内容

#### 5.5.1 删除策略（D4，按确认意见设计）

**核心规则**：删除行为由**文件大小**决定分流，阈值默认 **1 GB**，可在设置中调整。

| 文件大小 | 默认行为 | 用户可否改变 |
|---|---|---|
| **< 1 GB** | 放入**回收站**（可还原） | ✅ 可在删除确认框中主动勾选"彻底删除，不放入回收站" |
| **≥ 1 GB** | **直接永久删除**（不走回收站） | ⚠️ 必须通过红色二次确认才执行 |

**为什么这样设计**：超大文件放进回收站会挤占卷配额甚至失败（Windows 自身对超过回收站配额的文件也会退化为永久删除），
所以对 ≥1GB 走永久删除是符合系统惯例的；而小文件误删代价高、恢复成本低，默认保护。

**安全护栏（必须实现，不是可选项）**：

1. **二次确认文案必须写明后果**：
   ≥1GB 的删除确认框使用红色警示样式，文案为
   `文件「xxx.rar」大小 2.3 GB，超过 1 GB 阈值，将被【永久删除】且无法从回收站恢复。是否继续？`
2. **多选混删必须显式告知**：选中项中同时存在大小两类文件时，不静默执行，弹出三选一：
   - `仅删除小于 1GB 的 N 个文件（进回收站）`
   - `全部删除（其中 M 个大于 1GB 将被永久删除）`
   - `取消`
3. **阈值落在设置里**：`settings → 删除策略 → 永久删除阈值`，可改为 512MB / 1GB / 2GB / 5GB / 自定义；
   另提供全局开关"所有删除一律走回收站（忽略阈值）"，给保守用户一条退路。
4. **回收站失败自动降级提示**：若调用 Shell 回收站因卷配额/网络盘等原因失败，明确提示
   `该文件无法放入回收站（原因），是否改为永久删除？`，绝不静默永久删除。
5. **永久删除必须记录日志**：写入 `delete-journal.json`（路径、大小、时间、操作类型），
   永久删除不可撤销，但至少事后可追溯"删了什么"。
6. **网络路径（UNC/映射盘）**：通常无回收站，按"永久删除"流程处理并单独提示。

### M11 安装包（MSI）🚧 打包能力已完成，安装/升级/卸载需你在真机验证（2026-09-21）

用户需求：**做成安装包，放到另一台电脑就能直接装；原电脑已装过则支持更新（删旧版装新版）**。

**已实现的决策（你确认过）**：首次启动弹文件夹选择器 + 记住上次打开的目录；**仅当前用户安装**
（`%LOCALAPPDATA%\Programs`，**不弹 UAC**）；安装/升级时若程序在运行则**明确拒绝并提示关闭**。

**1) 补上"安装版必需"的那块能力**（绿色版不需要，所以此前一直是缺口）
- 新增 `store\MachineState`：机器级状态放 `%LOCALAPPDATA%\FilePanel\machine.json`，
  只存"上次管理的文件夹"。其余数据仍放在 `<被管理文件夹>\.filepanel\`——**数据跟着文件夹走**
- 此前 `RootResolver.resolve(options.root(), null)` 的"上次打开的文件夹"参数**一直传 null**，
  等于这个能力从未接上；绿色版不需要它，所以一直没暴露
- 安装模式由打包时注入的 `-Dfilepanel.installed=true` 标识（**显式标记，不靠猜路径**：
  "是否在 Programs 目录下"这种判断会在用户把绿色版解压到类似路径时误判）
- 判定抽成纯函数 `RootResolver.requiresFolderChoice(...)`，**可被单测覆盖**——
  弹窗本身没法自动断言，"什么时候该弹"可以
- 用户取消选择时**不退出程序**，退回主目录兜底并保留窗口：双击图标却什么都不发生是最糟的失败方式

**2) MSI 打包**（`scripts\package.cmd installer`）
- WiX Toolset 3.14 的**二进制 zip** 解压到 `tools\wix314\`：**不需要管理员权限、不写 Program Files**，
  工具链跟项目走（与 `tools\maven`、`tools\m2repo` 同一思路）。`node scripts\fetch-wix.mjs` 下载
- jpackage 参数：`--type msi --win-per-user-install --win-menu --win-shortcut --win-dir-chooser`
  `--java-options "-Dfilepanel.installed=true"`
- **升级语义靠版本号**：`APP_VERSION` 提高后重新打包、运行新 MSI，Windows 会**自动卸旧装新**，
  "应用和功能"里始终只有一条。**`APP_NAME` 不能改**——那是把两个版本认成同一个产品的东西
- 产物复制到工作区根目录：`FilePanel-安装版-1.0.0.msi`（44.4 MB）
